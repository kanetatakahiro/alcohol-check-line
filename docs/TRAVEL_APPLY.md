# 交通費申請の受付・照合・締切・給与反映シート（gas/TravelApply.gs・gas/PayrollSheet.gs 版 2026-11-19c・**本番未導入**）

紙の申請書の写真を公式LINEで受け付け → AI で読み取り・照合 → 管理本部が確認事項に回答 → 確定分を給与反映シート（社労士共有用【リバースHD】）の月のタブの「通勤手当」へ。
距離の表と照合（gas/Travel.gs・版 2026-11-18b）は docs/TRAVEL_DISTANCE.md。

## 1. 免許証の受付との見分け（調べた結果と選んだ方法）
- 今の振り分け（コード.gs の AC_handleEvent_）：画像はまず LIC_onUserEvent_（License.gs）へ。免許証が扱うのは「免許更新」「免許登録」・免許のボタン・**受付中（30分）の写真だけ**。それ以外の画像は問い合わせ（Inquiry.gs）へ流れている。
- 選んだ方法：**免許証のあと**に TA_onUserEvent_ を1行足す（コード.gs の変更はこの1行だけ。License.gs は変えない）。
  - 免許証の受付中の写真は、今までどおり免許証が先に取る（交通費は見もしない）。
  - 交通費が見るのは、免許証が取らなかった画像のうち、在籍・LINE確認済みで、「通勤距離」の通勤区分が「交通費申請（車・バイク）」「公共交通機関」の人のものだけ（ほかの人は AI も呼ばずに今までどおり問い合わせへ）。
  - AI が「交通費の申請書ではない」と答えた画像は扱わず、今までどおり問い合わせへ流す（保存もしない）。
- 理由：免許証のコード・指紋を変えずに済み、免許証の受付・読み取りは今までどおり動く（免許証の受付中の画像は必ず免許証が先）。申請の対象でない人の画像には AI の費用もかからない。
- AI の共用：License.gs の写真の取り出し（LIC_fetchPhoto_：やり直し・外部画像の対応つき）・API の宛先・版・既定のモデル・ANTHROPIC_API_KEY・返信（LIC_send_：遅いときはプッシュ）・「…」の表示を使う。指示と答えの形（JSON スキーマ）だけは申請書用（免許証用の形・エラーの記録は免許証専用のため）。

## 2. 記録（従業員マスタのファイル。新しいタブだけ）
| タブ | 中身 |
|---|---|
| 交通費申請 | 1申請1行：申請ID／受付日時／社員番号／氏名／対象月／反映月／状態（受付・要確認・確定・来月反映）／合計（円）／写真（ドライブのファイルID）／備考 |
| 交通費明細 | 1区間1行：申請ID／社員番号／日付／出発／到着／手段／km／金額（円）／TOT の出勤／照合結果／確認事項／**回答（管理本部が入力）**／**確認後の値（管理本部が入力）**／依頼の行 |
| 交通費の送る予定 | record のとき、送る代わりに書く（受付の返信・臨時の依頼・4日の催促・管理者のまとめ・エラーの知らせ） |
- 同じ人・同じ対象月・同じ反映月の写真は、同じ申請に足す（複数枚可）。LINE でまとめて送った写真（imageSet）は、最後の1枚のときだけ返信する。
- 写真は TRAVEL_APPLY_FOLDER_ID のフォルダに「社員番号_YYYYMMDD_HHmmss_n」で保存（**フォルダの共有は管理本部だけにしておく**。スクリプトは共有を変えない）。
- 本人への返信は受付の知らせだけ：「交通費申請の写真を受け付けました（11月分・4件）。…」。受付の締切後の前月分は「受付の締切（12/4）を過ぎて届いたため、来月のお給料での反映になります。」を足す。
- タブの見出しを並べ替えたり列を足したりすると、書き込みを止める（列のずれで違う欄に書かないため）。

## 3. 読み取り（推測しない）
- AI には写真と指示だけを送る（住所・氏名・LINE ID は送らない）。答えは JSON の形（対象年月・合計・各行の日付／出発／到着／手段／km／金額／読めない欄）。
- 読めない文字・数字は空にして「要確認」。読めた数字は手段がわからなくても残す。
- 年の無い日付（11/5）は、受け付けた月より後の月なら前の年。対象月が書かれていなければ、読めた日付がすべて同じ月のときだけその月（ばらばらなら要確認）。
- AI が使えない（キーなし・上限・エラー）ときも写真は保存し、申請書全体を要確認にする（管理本部が写真を見て明細を足す）。管理者へすぐ知らせる（同じ日・同じ人・同じ段階は1回）。

## 4. 照合
| 照合 | 要確認になるとき |
|---|---|
| 車・バイク（受付のとき） | TRV_checkSegment：申請の km が自動計算（高速を使わない道）より片道5km を超えて多い・行き先の店舗名／略語がわからない・距離を計算できない |
| 電車・バス | 金額が読めない（行き先は駅名なので店舗の照合はしない） |
| 金額 | 車・バイクは km × TRAVEL_YEN_PER_KM（既定15円）。申請の合計は「車・バイクの km の合計 × 15円（円未満切り捨て）＋電車・バスの金額」。申請書に書かれた合計と違えば要確認 |
| 日付 | 読めない・対象月の外 |
| 重複 | 同じ申請に同じ日・同じ出発・到着・手段がもう1行ある |
| TOT（毎朝） | tot-latest.json の日別勤怠（前月1日〜昨日）で、その日に出勤の記録（総労働が0より多い・エラー勤務・出勤の打刻）がない／記録の期間より前で確認できない／TOT の従業員コードがない |

## 5. 確認事項 → 毎朝の業務一覧
- 毎朝7時台（travelApplyDaily）：手で足した明細の照合 → TOT の照合 → 回答の確認 → 要確認の行を業務一覧ファイル（OFFICE_TASK_BOOK_ID）の「臨時の依頼」に**1件1行**で追加（8時の「今日の業務」に出る。土日祝は出ない）。
  - 業務名「交通費の確認：試験さん（11/5 赤井→自宅）」。住所らしい場所の名前は「（場所）」に伏せる。
  - メモ「何が・なぜ・どう直すか」。金額・km・住所は書かず、「交通費明細」の何行目かと申請ID を案内する。期限は回答の日（翌月5日。過ぎていれば今日）。
- スタッフは「交通費明細」の「回答」（必要なら「確認後の値」：車・バイクは km、電車・バスは円）を入れてから［完了］。日付・手段・出発・到着は、その欄を直接直してよい。
- 翌朝：回答か確認後の値が入った行を照合し直す（日付・手段・数字が読めるか）。読めれば「確認済み（12/4）」にして確定、臨時の依頼も「完了」にする（確認後の値で金額を計算し直す）。読めなければ、［完了］のあとに出し直す。
- 回答が空のまま［完了］になっていたら、確認事項を出し直す（新しい行。「回答が空のまま［完了］になっていました」を足す）。

## 6. 締切（版 2026-11-19b の決定）
| 日 | すること |

| 4日 10:00 | travelApplyRemind：前月分の申請が無い「交通費申請（車・バイク）」の在籍者へ個別 LINE（土日祝も日付どおり。同じ月・同じ人は1回。LINE 未登録の人には送れない） |

## 7. 給与反映シート（社労士共有用【リバースHD】）— gas/PayrollSheet.gs（版 2026-11-19c：本番で確かめた形に合わせた）
本番で確かめた形（2026-11-19。見出しと形だけで、金額・氏名は見ていない）。新しい「雛形」や新しい列は作らない。
- 月のタブ：「R{令和}.{M}月分{M+1}月支給」（例 R8.10月分11月支給）。今月分は先頭に★が付く（★・☆・空白は無視して同じ月として扱う）。「テンプレ」タブがある。
- ほかのタブ（隠しタブ・「固定精算の開始・内容について」「固定立替詳細」「交通費計算シート」「従業員コード」など）は触らない。
- 1行目：B列「2026年」・C列「11月支給」（2つのセル）。
- 2行目の見出し：B 従業員番号／C 氏名／D 立替経費／E 通勤手当／F 固定立て替え／G **家賃補助**／H インセンティブ／I 合計（各行 =SUM(D:H)。小文字の =sum の行もある）。**列は見出しの名前で探す**（位置は決め打ちしない）。
- 3行目から1人1行（今は金額がある人だけ）。人の並びのすぐ下に**合計の行**（D〜I が =SUM(D3:D25) の形。テンプレは26行目、10月分は37行目で、月によって位置が変わる）。人の並びの終わりは「従業員番号・氏名が空で、最初の金額の列（立替経費）が =SUM の行」で見つける。
- 合計の行の3行ほど下に固定立て替えの表（D 内容／F 合計金額／G 支払い回数／H・I 期間／J 当月徴収金額）。L列にチェックボックス、M列に「修正箇所」などのメモ。**合計の行より下と、合計の列より右（L・M）には書かない。**

書き込みの決まり：
- 締めの月のタブが**無ければ**「テンプレ」をコピーして作り、1行目 B・C に支給の年と月を入れる。テンプレに入っている人の行（3〜25行目）は**消さずに使い**、いない在籍者だけを足す。作ったタブだけ、人の行に「金額の列の合計が0なら灰色 #efefef・0でなければ白」の条件付き書式を足す。テンプレそのものは変えない。
- **人を足すとき**：人の並びの中の空いている行（従業員番号・氏名とも空）を先に使い、足りなければ**合計の行の上に行を挿入**する。挿入した行には上の人の行の式（合計の列など）を同じ形で入れ、合計の行の =SUM の範囲を広げる（=SUM(D3:D25) → =SUM(D3:D28)。シートが自動で広げていればそのまま）。行ごと挿入するので、下の固定立て替えの表と L・M 列は中身を変えずにそのまま下へずれる。
- タブが**あれば**そのタブに書く。書く金額がある人が並んでいなければ、同じやり方で足して管理者への一覧に「行を足した」と出す。そのほかの行・列・数式・書式は変えず、条件付き書式も足さない。
- 書く列：**「通勤手当」**（交通費の確定額。定期（固定額）の人は「通勤距離」タブの固定額）。従業員番号が一致する行の、空いている欄だけ。
  - 値か式がある欄：上書きしない（同じ値なら何もしない）。違う値は管理者への一覧に「すでに値があるため書かなかった」として出す。
  - 在籍者に見つからない従業員番号：書かずに一覧に出す。
  - 見出しに「従業員番号」「氏名」「合計」や書く列が無い、または合計の行が見つからないタブ：何も書かずに止めて知らせる（直したあと travelApplyCloseAgain でやり直す）。
- 共通の関数 **PAY_writeColumn_(月, 列の名前, [{ code, value }], { people, mode })**：今後の AI の経費申請（立替経費）も、列の名前「立替経費」を渡せば同じ決まりで書ける。通勤手当・立替経費・合計（シートの式）がそれぞれわかる形を保つ。
- 区間ごとの明細は、従業員マスタのファイルの「交通費申請」「交通費明細」に残す（給与反映シートには金額だけ）。
- **構成の確認**：travelApplyInspectSharoushi（＝PAY_inspect。読むだけ）が、タブごとに次をログに出す。氏名・金額は出さない。**本番で一度実行して、結果を見てから on にする**（下の手順4）。
  - 名前・行数・列数・1行目・2行目（見出し）・固定した行・条件付き書式の数
  - 合計の行の位置と式・人の行の数と空いている行の数・人の行の合計の式・見出しに無い金額の列
  - 今月・前月のタブがどれに当たるか

## 10. 元に戻す方法
- すぐ止める：TRAVEL_APPLY_MODE を消す（off。画像は今までどおり問い合わせへ。毎朝・4日の処理も何もしない）。
- トリガー：travelApplyRemoveTriggers。
- コードを戻す：コード.gs を 17e（`1f145c99225c987a`）に戻して再公開（TravelApply.gs・PayrollSheet.gs が残っていても、受け口が無ければ写真は扱わない）。2つのファイルは消してよい。
- 従業員マスタのファイルに作ったタブ（交通費申請・交通費明細・交通費の送る予定）は消してよい。「臨時の依頼」に足した行は、状態を「取り消し」にすれば業務一覧に出なくなる。
- 給与反映シート：締めでテンプレから作った月のタブは消してよい。既存のタブに書いたのは空いていた「通勤手当」の欄と、足した人の行だけ（管理者への一覧に出る）。消すときはその欄を空にし、足した行を消す（合計の行の =SUM の範囲は行を消すと自動で縮む）。

## 11. 影響・費用
- 「臨時の依頼」の行が増えるぶん、平日朝の業務一覧の件数が増える。
- 4日の催促は人数分の LINE の通数（push）を使う（未提出の人だけ）。受付の知らせは返信（通数にかからない。遅いときだけ push）。
