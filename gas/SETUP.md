# Apps Script の設定手順

シフト表の「出勤」とフォーム回答を照合し、未実施者本人（公式LINEと1対1）と管理者へ通知します。
管理シート（アルコールチェック管理シート）は読み取りのみで、書き込みはしません。
従業員の情報は、別ファイルの「従業員マスタ」で社員番号をキーに管理します（他業務の自動化でも共通で使う）。

## 1. LINE側（LINE Developers / 公式アカウント「REBIRTH 管理本部」）
1. Messaging APIチャネルの「チャネルアクセストークン（長期）」を発行する。
2. 「チャネル基本設定」の「あなたのユーザーID」（Uから始まる）を控える（管理者宛ての通知先）。
3. 管理者のLINEで公式アカウントを友だち追加する（未追加だと届かない）。
4. Webhook URL を、このプロジェクトのWebアプリURLに差し替える（手順2-8）。

## 2. Apps Script
1. 会社アカウント mayu.ando@rebros.info（シート編集者）で、独立プロジェクト
   「アルコールチェック通知（暫定版）」を使う（2026-10-08作成）。
   ※既存の「アルコールチェックLINE自動通知」（Webhook用）は個人Gmailの所有のため使わない。
   アカウントが食い違うと権限承認が通らない。
2. `gas/AlcoholCheck.gs` の内容をコード.gsに貼り付けて保存する。
3. 「プロジェクトの設定 → スクリプト プロパティ」に次を設定する。
   - `LINE_CHANNEL_ACCESS_TOKEN`：1-1のトークン
   - `LINE_ADMIN_USER_ID`：1-2のユーザーID
   - `DRY_RUN`：最初は `true`（送信しない）
   - `NOTIFY_EMPLOYEES`：本人通知を始めるときに `true`（未設定なら管理者一覧のみ）
4. `alcoholCheckPreview` を実行し、権限承認をする。実行ログで対象人数・未実施者を確認する。
5. `alcoholCheckSendTestMessage` で管理者のLINEに届くことを確認する。
6. `alcoholCheckSetupMaster` を実行し、従業員マスタを作成する。
   シフト表の氏名が入るので、管理者が社員番号・所属を入力する。
7. `alcoholCheckSetupTriggers` を実行する（毎日 8:30 朝の案内／10:00 出勤前の入力確認／18:30 退勤前の案内／20:00 退勤前の入力確認と感謝／10分ごとの飲酒検知の確認）。
8. 「デプロイ → 新しいデプロイ → ウェブアプリ」（実行：自分、アクセス：全員）で公開し、
   URLを LINE Developers の Webhook URL に設定する。
9. 従業員が公式LINEを友だち追加し、社員番号だけを送る → マスタの該当行にLINE IDが入る。
   管理者が本人であることを確認し「LINE確認済み」にチェックする。
10. 確認できたら `DRY_RUN` を `false`、`NOTIFY_EMPLOYEES` を `true` にする。

## 従業員マスタの列
社員番号／氏名／別表記（シフト表の書き方が違う場合）／在籍状況（在籍・休職・退職）／所属・拠点／
LINEユーザーID／LINE表示名／LINE登録日時／LINE確認済み／アルコールチェック対象／備考
- 既に別のLINE IDがある社員番号への登録は上書きせず、「LINE登録の要確認」シートに残す。
- 本人通知に使うのは「LINE確認済み」「アルコールチェック対象」がチェック済みで、退職でない行だけ。

## 判定の内容
- 対象：シート「2026-2028」のシフト行で、当日が「出勤」の人
- 実施済み：「フォームの回答 1」に当日（日本時間）・同じ区分の回答がある人
- シフト表の氏名と、マスタの氏名・別表記を照合（空白の違いのみ同一視）。同名がいると使わない。
- 測定結果の値は判定に使わない。
- 当日の日付列がない等の不備は、本人には送らず、管理者へ「確認できませんでした」と送る。
- 同じ日・同じ人・同じ区分は1回だけ送る。

## 毎日の通知
| 時刻 | 宛先 | 内容 |
|---|---|---|
| 8:30 | 出勤者全員 | あいさつ＋天気（気象庁・埼玉県南部／さいたまの気温）＋運転前のチェック案内 |
| 10:00 | 出勤前の入力が確認できない人 | 入力のお願い（未実施と決めつけない文面） |
| 18:30 | 出勤者全員 | 退勤前のチェック案内 |
| 20:00 | 退勤前の入力が確認できない人 | 入力のお願い |
| 20:00 | 連続記録が節目（5・10・20・30・40・50日、以降10日ごと）の人 | 感謝のメッセージ |
- 連続記録：シフトが「出勤」の日だけを数え、出勤前・退勤前のどちらかが欠けたら0に戻る（休みの日は飛ばす）。
- Apps Scriptの時刻指定は前後15分程度ずれる。
- 測定結果が0.14mg/L以下と読めない回答は、10分ごとの確認で管理者へ至急の確認依頼（`ALERT_THRESHOLD` で変更可）。
- `REQUIRE_DEVICE=true` のとき、管理シート「アルコールチェッカー在庫」の「機器所持」にチェックがある人だけに本人通知する（機器が届いたらチェックを入れるだけで対象になる）。
- テストモード：`TEST_CODES`（社員番号）と `TEST_UNTIL`（期限）を設定すると、その人宛ての通知を管理者へ送る。
- `alcoholCheckEstimate`：今日の見込み通数、`alcoholCheckUsage`：日ごとの見込み通数（全員登録済みの場合）。

## 費用
LINEの無料プランは月200通。出勤者全員への朝・夕の案内を送ると月700通前後になり、ライト（月5,000円・5,000通）が必要。テスト中の見込み通数を見て決める。
社員番号の登録への返信は応答メッセージのため通数に含まれない。Apps Scriptは無料。

## 設定と版の確認（alcoholCheckShowSettings）
- エディタで `alcoholCheckShowSettings` を選んで実行 → 実行ログに表示されます。LINE送信・シートへの書き込みはしません。
- 表示されるもの：コードの版（`AC_CODE_VERSION`）、オン／オフ等の設定値（未設定なら既定の動き）、トークン・合言葉・ID・社員番号は「設定あり／なし」だけ、登録済みのトリガー（重複・旧CSV取り込みの残りも表示）、VPSからTOTデータが最後に届いた日、翌月シフト反映が済んだか。
- **コードを変更したら `AC_CODE_VERSION` を必ず更新する**。Apps Scriptで表示される版と、GitHubの `gas/AlcoholCheck.gs` の版が同じなら、貼り付け漏れがないと判断できます。
- 記録（状態）は実行したアカウントごとに分かれます。**所有者アカウント（mayu.ando@rebros.info）で実行**してください。

## 翌月シフト反映が失敗したときの再実行（手動）
自動反映（月末の朝7:05）が終わらなかったときだけ使います。**既存データの上書きを防ぐため、必ずプレビュー → 確認 → 実行の順**です。所有者アカウントで行ってください。

### 安全のしくみ
- `alcoholCheckPreviewNextMonthShift`（プレビュー）は**書き込みをしません**。どのセルがどう変わるかを実行ログに出すだけです。
- `alcoholCheckRunNextMonthShift`（実行）は、**プレビューから30分以内で、プレビューの後に管理シートもTOTデータも変わっていないとき**だけ反映します。誰かがシートを直していたら止まります。
- その月の反映が**すでに済んでいる**（自動でも手動でも）ときは実行しません（反映後に人が直したセルを守るため）。
- **今日より前の日**と**数式のセル**は書き換えません。`TOT_MONTHLY_APPLY=false` のときも実行しません。
- 反映の中身は自動反映と同じです（違うセルだけ・TOTに予定がない日は空欄のまま・結果と元の値を「TOT翌月シフト反映」シートに記録・件数を管理者のLINEへ）。

### (a) VPSは動いたが、Apps Scriptの処理が失敗した場合（エラー通知が届いた等）
1. 月末当日の**22:30より前**に行う（22:30の夜の取り込みで、保存データから翌月分が消えるため）。
2. `alcoholCheckPreviewNextMonthShift` を実行し、実行ログの書き換え予定を確認する。
3. 問題がなければ30分以内に `alcoholCheckRunNextMonthShift` を実行する。
4. 22:30を過ぎた場合は、翌月1日の朝7:05の取り込みの後（当月の予定が入ったデータ）で同じ手順を行う。今日より前の日は書き換えないので、1日分などは手で直してください。

### (b) VPSが動かなかった場合（「今朝のTOTの取り込みが届いていません」の通知等）
1. さくらのVPSのコントロールパネルで稼働中か確認する。
2. VPSにログインし、次を**月末当日の 10:00〜17:30 または 18:30〜20:00 のあいだ**に1回だけ実行する（TOTの利用禁止時間帯 8:30〜10:00・17:30〜18:30 を避ける。20時以降は夜の取り込み扱いになり翌月分を取らない）。
   ```
   cd ~/alcohol-check-line && node --env-file=.env src/tot-relay.js
   ```
   （アプリの場所が違う場合は `deploy/server-setup.sh` で設定した場所。結果は画面と `~/tot-relay.log` に件数と状態だけが出ます）
3. 月末当日なら、届いた時点で**自動反映がそのまま動きます**（まだ済んでいない場合）。管理者のLINEに【○月のシフト反映】が届けば完了です。届かなければ (a) の手順へ。
4. 翌月1日以降に気づいた場合は、1日〜7日の朝の取り込みの後に (a) の2〜3を行う。
- 補足：手動の取り込みでも、勤怠チェック表や36協定などのシートが更新されます。管理者への同じ種類のお知らせは1日1回まで・36協定は新しく該当したときだけなので、二重には届きません。本人へのお知らせは夜の取り込みのときだけなので届きません。

## 旧CSV取り込み（alcoholCheckImportTot）について（2026-10-16 調査）
- 1時間ごとにドライブの「TOT取り込み」フォルダを見て、**新しい .csv があるときだけ**処理します。CSVが無ければ何もせず終わります（`tot-latest.json` は対象外）。
- CSVが置かれた場合：従業員マスタの「TOT取り込み」シートを**消して書き直す**ため、API連携の朝の比較結果を上書きします。`TOT_APPLY=true` のときは、そのCSVの内容で今日以降のシフトも書き換えます。
- 止める場合は、トリガー画面で `alcoholCheckImportTot` の1つを削除します。ただし `alcoholCheckSetupTriggers` を再実行すると登録し直されるため、止めると決めたらコード側からも外す必要があります（未対応）。アルコールチェックの通知・飲酒検知の確認には影響しません。
