# 社員管理AI（第1段階：入社・退社・取消）

状態：開発ブランチ `feature/employee-admin` で完成・テスト済み。**本番未導入**（本番反映・Webhook切り替え・自動反映は別途承認）。

## できること
| 操作（勤怠管理グループで送る） | 動き |
|---|---|
| `入社` / `退社` / `取消` の一言 | 入力の雛形を返信（`取消` は取消できる申請の一覧つき） |
| `【入社】…` / `【退社】…` | 形式チェック・従業員マスタと照合 → 申請番号（EA-YYYYMMDD-連番）と「承認」「却下」ボタンを返信 |
| 「承認」ボタン（`承認 申請番号 6桁コード`） | グループの誰でも承認可（本人も可）。72時間以内・1回限り → 予約 |
| `【取消】申請番号：…` | 反映前（申請中・予約）なら取消。AIが作ったお知らせ停止の行も消す |
| 毎朝の処理（`employeeAdminDaily`） | 期限切れの処理、効力日が来た予約を従業員マスタへ反映（`EA_AUTO_APPLY=true` のときだけ）、グループへ結果報告 |

- 効力日：入社＝入社日、退社＝退職日の翌日（D列＝退職、N列＝退職日を**文字**で）
- 入社：15列の行を追加（A列社員番号・M列TOTコード・O列入社日は文字。I・J列はチェックボックス）。入社前に本人がLINE登録していれば、その行に書き込む
- 退社：最終出社日が退職日より前なら、承認時に「お知らせ停止」へ最終出社日の翌日〜退職日の行を追加（G列＝社員管理AI、H列＝申請番号）
- 照合：社員番号の再利用不可（退職者含む）、在籍者とのTOTコード重複不可、過去日付は7日前まで（警告）、退社は社員番号と氏名の一致、二重申請は警告
- 別表記：第1段階はC列（既存の読み取り先）に書き、「別表記」シート（社員番号キー・複数可の将来の正本）にも記録
- 記録：`社員管理_申請`（状態）、`社員管理_変更履歴`（変更前後）、`社員管理_操作ログ`（誰が何をしたか）

## 安全対策
- **LINE署名確認**：LINE → VPSの中継（`src/line-relay.js`）が `X-Line-Signature` を確認 → 合言葉の署名・5分以内・使い捨て番号つきで Apps Script（`type: 'line-verified'`）へ転送。署名を確認できない今の直結経路では、社員管理は一切動かない
- **承認者の確認**：勤怠管理グループ（「LINEグループ」シートで「勤怠管理」）のメッセージだけを扱い、送信者が今もメンバーかを毎回 LINE に問い合わせる。送信者が分からない（パソコン版LINE等）場合は受け付けない
- **重複防止**：webhookEventId・転送の使い捨て番号を記録して二重処理しない。承認コードは1回限り
- **段階的な有効化**：`EA_MODE` 未設定＝何もしない／`record`＝記録のみ／`on`＝利用開始。`EA_AUTO_APPLY=true` で初めてマスタへ自動反映

## 既存システムへの影響
- `AlcoholCheck.gs` の変更は doPost の1分岐（`line-verified`）と版番号のみ。既存の LINE・TOT中継の経路は変更なし
- 署名確認済みの経路で届いた社員管理以外のイベント（1対1の社員番号登録・部門登録など）は、今までと同じ `AC_handleEvent_` で処理
- 従業員マスタ O列（入社日）とお知らせ停止 G・H列を追加。既存処理は14列・6列までしか読まず、`AC_markRetired_`・名簿取り込みもO列を消さないことを確認済み

## 本番導入の手順（すべて別途承認後）
1. 11/1〜の打刻記録の安定を確認
2. DNS（例 line.rebros.info）→ VPSにHTTPS証明書 → `deploy/line-relay/`（nginx・systemd・line-relay.env）で中継を起動。既存の cron・.env は変更しない
3. 本番Apps Scriptに `EmployeeAdmin.gs` を追加し `AlcoholCheck.gs` を差し替え（版 2026-10-26ea）。新しいデプロイ版を作り、同じURLのまま反映
4. スクリプトプロパティ `EA_FORWARD_SECRET` を設定（`EA_MODE` は未設定のまま）
5. LINE Developers の Webhook URL を中継のURLへ切り替え（元に戻す場合は Apps Script のURLへ戻すだけ）→ 既存機能（社員番号登録・部門登録）の動作確認
6. `EA_MODE=record` で数日観察 → `EA_MODE=on`（申請・承認のみ）→ `employeeAdminDaily` のトリガー（5時台・7時台）→ `EA_AUTO_APPLY=true`

戻し方：`EA_MODE` を削除（即時停止）。Webhook URL を Apps Script のURLへ戻せば、中継を通らない元の状態に戻る。
