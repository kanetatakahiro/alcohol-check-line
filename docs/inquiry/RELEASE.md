## 付録1：Webhookの中継（Cloudflare Workers・LINE署名検証）の現在の状況と、問い合わせを乗せる場合・乗せない場合の違い

### 現在の状況（2026-11-05 時点、GitHub の記録より）
- **中継のプログラムは完成しています。** ブランチ `feature/employee-admin`（最終コミット d17b687・10/27）の `workers/line-webhook/` にあり、単体テスト済みです。**main には統合されていません。**
- 中継の動き：
  1. LINEの署名（改ざん防止の印）を確かめ、合わなければ捨てます（401）。
  2. 既存の Apps Script へ、受け取った本文をそのまま転送します（全部のイベント）。
  3. 勤怠管理グループのイベントだけを、合言葉の署名つきで社員管理AIへ転送します。
  4. 転送に失敗した分は一時保存し、5分ごとに最長24時間、再送します。
- **LINE の Webhook URL の切り替えは、記録上はまだです。** gas/EMPLOYEE_ADMIN.md は「切り替え前の記録（10/27 11:00・変更なし）」で止まっていて、その後に切り替えた記録は GitHub にありません。
  - 実際の状態は、LINE Developers →「Messaging API設定」→「Webhook URL」が Apps Script（script.google.com）か Workers かで確かめられます（見るだけ）。
- 切り替えに必要な作業（未実施・別途承認）：
  - Cloudflare のアカウント・Worker の作成と公開
  - シークレット（チャネルシークレット・転送用の合言葉）の登録
  - 社員管理AI（本番）の準備
  - Webhook URL の切り替えと検証
- 社員管理AI（本番）は、記録のみモード（EA_MODE=record）で作成済みです（10/27 の記録）。

### 問い合わせを中継に乗せる場合と乗せない場合
「乗せない」は、LINEから Apps Script へ直接届く今の経路のままにすることです。「乗せる」は、Webhook URL を Workers に切り替えた後の経路で動かすことです。問い合わせのコードは、どちらでも変更なしで動きます。

| 比べる点 | 乗せない（今の経路） | 乗せる（Workers 経由） |
|---|---|---|
| 必要な作業 | なし（この手順書のとおり） | Workers の切り替え（社員管理AIの導入と同じ作業）。問い合わせのための Workers の変更は不要 |
| 本物のLINEからの受信かどうかの確認 | できない（Apps Script はLINEの署名を読めない） | Workers で署名を確かめ、偽のデータは Apps Script に届かない |
| 偽のデータへの守り | 送信者のプロフィール確認、グループのメンバー確認、案件ごとの合言葉で防ぐ | 左の守りに加えて、署名で入口で止める（二重の守り） |
| 受け口のURLが知られている影響（「補足」） | 偽の1対1メッセージは、プロフィールが取れない限り案件にならない。偽のボタンは合言葉が無いと効かない | 署名の無いデータは届かないので、URLが知られていても影響しない（Workers のURL宛て） |
| 重複受信 | LINEの再送はオフなので、ほぼ起きない | Workers の再送（最長24時間）で、同じイベントが2回届くことがある。受信記録（直近2,000行）と一時記憶で防ぐ（テスト済み） |
| 届かなかったとき | Apps Script が止まっていると、その間のイベントは失われる | Workers が一時保存して再送するので、失われにくい |
| 社員管理AIとの関係 | 関係なし | `EA_GROUP_ID` を設定すると、勤怠管理グループの問い合わせのボタンも社員管理AIに届く（社員管理AIは文字のメッセージ以外を無視するので害はない）。無駄を省くなら、社員管理AIへの転送を「文字のメッセージと `ea|` で始まる postback」に絞る（Workers の変更・別途承認） |
| 応答の時間 | LINE → Apps Script（今と同じ） | Workers を通る分の少しの遅れ（Workers は最大28秒待つ） |
| 戻し方 | 「デプロイを管理」で前の版へ | 左に加えて、Webhook URL を Apps Script に戻す（1分） |

- おすすめ：問い合わせの導入は、中継の切り替えを待たずに進めて問題ありません。切り替えた後も、そのまま動きます。
- 中継に乗せた後に、さらに守りを強める案（第2段階・Workers と Apps Script の変更が必要）：
  - 既存の Apps Script への転送のURLに、時刻と合言葉の署名（`?ts=…&sig=…`）を付けます。
  - 問い合わせの処理は、印のあるものだけを受け付けます。
  - 本文はそのままなので、既存の処理は変わりません。
