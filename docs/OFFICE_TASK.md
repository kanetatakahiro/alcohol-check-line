# 事務の業務一覧LINE（AI上司）（gas/OfficeTask.gs・版 2026-11-17d）

## 何をするか
- **だれか1人に固定しない。** 管理本部のみんなあてに「今日のお仕事」を送り、ボタンを押した人が担当になる（担当の人が替わっても設定の変更は不要）
- 平日の毎朝8時台に、事務業務のグループ（「部門登録 事務業務」で登録）へ送る。土日・祝日（振替休日・国民の休日を含む）と OFFICE_TASK_OFF_DATES の日は送らない。勤怠管理グループには送らない
- 土日祝などに対応するときは、グループで「今日の業務を教えて」と送ると、その場で今日の一覧（ボタン付き）を返信する（返信なので通数にかからない）
- 仕事の元：スプレッドシート「【事務業務】業務一覧・マニュアル」の「業務マニュアル」（任せる＝○の行）と「臨時の依頼」
- 期間に入っているお仕事・期限を過ぎたお仕事（7日以内）・臨時の依頼は、すべて一覧に入れる（期限が近い順、朝の確認が最初）。前倒しできる分は［手が空きました］で1件ずつ
- ボタン：［完了］［対応します］［わからない］［今日はできない］［手が空きました］。グループのメンバーなら誰でも押せて、押した人（従業員マスタの姓、無ければLINEの表示名）を担当・完了者として記録。合言葉は日ごと、前の日のボタンは使えない
- ［完了］のあとに［間違えたので取り消す］（完了にした人と管理者だけ）。同じ仕事の2回目の完了は受け付けない
- グループで「残りの業務」「未完了の業務を教えて」などと送ると、今日の未完了のお仕事（担当つき）とボタンを返信
- 業務マニュアルの「AI化の状況」が「AI化済み」の行は指示しない
- 12時（10分ごとの確認）に、残っているお仕事をグループへお知らせ（朝に送った日だけ・1日1回）。週の最初の平日の朝は先週のまとめ（完了した人・わからない・できなかった）
- 記録：「今日の仕事の記録」（押した操作）・「送る予定の内容」（毎朝の一覧）

## 予定ルール（業務マニュアルの「AI用の予定ルール」列。OT_setup が空欄に既定値を入れる）
| ルール | 意味 | 例 |
|---|---|---|
| daily | 毎日 | M01・M02・M10 |
| weekly:5 | 毎週その曜日（0=日〜6=土）。過ぎても7日間は残す | M03（金） |
| monthly:1~3 | 毎月1日〜3日 | M04 |
| monthly:-2~3 | 前月の末日の2日前〜3日 | M05 |
| yearly:11/1~12/20 | 毎年の期間 | M18 |
| request | 「臨時の依頼」に書いたときだけ | M12〜M17・M19・M20 |
| reserve | 一覧に出さず、時間だけ確保 | M21 |
| spare | 出さない（空き時間用の説明） | M22 |

## 設定（スクリプトプロパティ）
- OFFICE_TASK_MODE：未設定＝何もしない／record＝送らずに「送る予定の内容」へ記録／on＝送信
- OFFICE_TASK_BOOK_ID：業務一覧・マニュアルのスプレッドシートID
- OFFICE_TASK_OFF_DATES：土日祝のほかに送らない日（任意。例「12/29,12/30,12/31,1/2,1/3」）
- （版 2026-11-17c まであった OFFICE_TASK_STAFF は使わない。17d で削除）
- OFFICE_TASK_GROUP：送り先の部門名（未設定＝事務業務）

## 運用上の注意
- グループへのプッシュは、グループの人数分の通数になる見込み（LINE の数え方は「送信数×送信対象の人数」）。平日の毎朝1回＋12時1回（週の最初の平日はまとめでもう1回）。返信（ボタン・「残りの業務」）は数えない
- グループに出す文に個人情報（マイナンバー・給与・健康・家族）を書かない。「臨時の依頼」のメモも同じ
- 勤怠管理グループの表示名を変えても仕組みには影響しない（仕組みは「LINEグループ」シートの部門名で送り先を決める）

## AI化の順番と指示の切り替え（版 2026-11-17c）
- 「AI化の順番（まゆさん用）」：順番・状況・メモはまゆさんが自由に変えてよい。灰色の列（稼働の確認）は Claude と毎朝の処理が書く
- 人への指示を止めるのは「状況＝AI化済み」かつ「稼働の確認（結果）＝確認済み」のときだけ。AIの機能を本番に入れるときに、Claude が稼働の確認（設定）に確認方法（スクリプトプロパティ名=値）を入れる
- 状況を先に「AI化済み」にしても、稼働が確認できるまで人への指示は続く（漏れを防ぐ）
