# 交通費申請の受付・照合・締切・給与反映シート（gas/TravelApply.gs 版 2026-11-20a・gas/PayrollSheet.gs 版 2026-11-19e・**本番未導入**）

紙の申請書の写真を公式LINEで受け付け → AI で読み取り・照合 → 管理本部が確認事項に回答 → 確定分を給与反映シート（社労士共有用【リバースHD】）の月のタブの「通勤手当」へ。
距離の表と照合（gas/Travel.gs・版 2026-11-20a）は docs/TRAVEL_DISTANCE.md。

## 1. 免許証の受付との見分け（調べた結果と選んだ方法）
- 今の振り分け（コード.gs の AC_handleEvent_）：画像はまず LIC_onUserEvent_（License.gs）へ。免許証が扱うのは「免許更新」「免許登録」・免許のボタン・**受付中（30分）の写真だけ**。それ以外の画像は問い合わせ（Inquiry.gs）へ流れている。
- 選んだ方法：**免許証のあと**に TA_onUserEvent_ を1行足す（コード.gs の変更はこの1行だけ。License.gs は変えない）。
  - 免許証の受付中の写真は、今までどおり免許証が先に取る（交通費は見もしない）。
  - 交通費が見るのは、免許証が取らなかった画像のうち、在籍・LINE確認済みで、「通勤距離」の通勤区分が「交通費申請（車・バイク）」「公共交通機関」の人のものだけ（ほかの人は AI も呼ばずに今までどおり問い合わせへ）。
  - AI が「交通費の申請書ではない」と答えた画像は扱わず、今までどおり問い合わせへ流す（保存もしない）。
- 理由：免許証のコード・指紋を変えずに済み、免許証の受付・読み取りは今までどおり動く（免許証の受付中の画像は必ず免許証が先）。申請の対象でない人の画像には AI の費用もかからない。
- AI の共用：License.gs の写真の取り出し（LIC_fetchPhoto_：やり直し・外部画像の対応つき）・API の宛先・版・既定のモデル・ANTHROPIC_API_KEY・返信（LIC_send_：遅いときはプッシュ）・「…」の表示を使う。指示と答えの形（JSON スキーマ）だけは申請書用（免許証用の形・エラーの記録は免許証専用のため）。

## 3. 読み取り（推測しない）
- 申請書（v2・版 2026-11-19f から）：A4・1枚。1行目に対象（年・月分）／社員番号／氏名（所属・店舗の欄は無い）。
  表は No／日付（月/日）／方法（車・バイク・電車・バスのどれか1つに○）／出発地／到着地／往復・片道（どちらかに○）／片道（km）／合計（km）／運賃（円）の30行。
  表の上の薄い文字の「記入例：」の1行は申請ではないので読まない。高速料金・備考の欄は無い（高速・駐車場は立替経費で別に申請する。高速料金は読まない・計算しない）。
  下に手書きの合計（合計kmの合計・運賃の合計）。
- 申請書 v3（版 2026-11-19g から）：右上に「枚数：□枚目／全□枚」。表は1枚25行（列は v2 と同じ）。下の合計欄は4つ（どれもその用紙の分）：
  ①合計kmの合計（車・バイク）／②車・バイクの金額（①×15円）／③運賃の合計（電車・バス）／④交通費の合計（②＋③）。
  AI には枚目・全枚数と①〜④も読ませる（書いていない欄は ""、読めない欄は空のまま。計算して埋めない）。
- AI には写真と指示だけを送る（住所・氏名・LINE ID は送らない）。答えは JSON の形（対象年月・手書きの合計km・手書きの運賃の合計・各行の記入例か／日付／方法／出発／到着／往復・片道／片道km／合計km／運賃／読めない欄）。
- 「記入例」の行は二重に除く：AI に読ませない指示に加えて、AI が記入例の印を付けた行と、どこかの欄に「記入例」と書かれた行は記録しない。
- 方法・往復・片道の○が無い・2つ以上（両方）・読めないときは、空のまま要確認。km の欄が読めないときは、もう片方から計算しない。
- 読めない文字・数字は空にして「要確認」。読めた数字は手段がわからなくても残す。
- 年の無い日付（11/5）は、受け付けた月より後の月なら前の年。対象月が書かれていなければ、読めた日付がすべて同じ月のときだけその月（ばらばらなら要確認）。
- AI が使えない（キーなし・上限・エラー）ときも写真は保存し、申請書全体を要確認にする（管理本部が写真を見て明細を足す）。管理者へすぐ知らせる（同じ日・同じ人・同じ段階は1回）。

## 4. 照合
| 照合 | 要確認になるとき |
|---|---|
| 車・バイク（受付のとき） | TRV_checkSegment：**片道（km）** が自動計算（高速を使わない道）より片道5km を超えて多い・行き先の店舗名／略語がわからない・距離を計算できない |
| 往復・片道（19f） | ○が無い・両方に○。車・バイクの往復は 合計km＝片道km×2、片道は 合計km＝片道km（小数1桁まで同じなら OK）。合わなければ要確認（合計は書かれたまま）。片方しか書いていなければ、もう片方を計算する（要確認にしない） |
| 電車・バス | 運賃が読めない（行き先は駅名なので店舗の照合はしない）。運賃は書かれた金額のまま（往復なら往復分が書いてある前提。2倍にしない） |
| 金額 | 車・バイクは 合計km × TRAVEL_YEN_PER_KM（既定15円）。往復・片道がわからない行は金額を出さない。申請の合計は「車・バイクの合計km の合計 × 15円（円未満切り捨て）＋電車・バスの運賃」 |
| 合計欄①〜④（19g・用紙ごと） | ①と、その用紙の車・バイクの行の合計（km）の合計／②と、①×15円（四捨五入）／③と、その用紙の電車・バスの行の運賃の合計／④と、②＋③。違えば申請書全体を要確認。**書いていない欄・読めない欄は比べない**（空欄だけでは要確認にしない）。読めない行があればその合計は比べない。④は、②・③が書いていなくても、その種類の行が無い用紙なら 0 として比べる |
| 枚数（19g） | 同じ人・同じ対象月の写真は1つの申請にまとめる（今までどおり）。全N枚のうち届いていない枚目があれば、申請書全体の行に「届いていない枚目があります（2枚目が届いていません）」で要確認。あとでその枚目が届けば、その行を自動で「確認済み（全部の枚目が届いた）」にする（臨時の依頼も完了）。全枚数は、届いた写真の「全□枚」と「□枚目」のいちばん大きいもの |
| 同じ枚目（19g） | 同じ枚目が2回届いたら、あとの写真を使う（要確認にしない）。前の写真の明細（その用紙の合計欄の確認事項も）は「差し替え（2枚目を送り直し）」にして、合計・TOT の照合・重複の判定に入れない（行は消さない。臨時の依頼の行の番号がずれないため）。開いている臨時の依頼は「取り消し」 |
| 枚目の本人への知らせ（19h） | 受付のときの返信には足さない（まとめて送った写真の途中で知らせないため）。15分ごと（travelApplyPagesRemind）に、**最後の写真から1時間たっても**届いていない枚目がある申請だけ、本人へ個別 LINE：「10月分の交通費申請書の2枚目が届いていません。写真を送ってください。」（金額・km・場所は書かない）。写真が届くたびに1時間を数え直す。送るのは 8時〜21時台だけ（夜の写真は朝8時台に）。同じ申請の同じ枚目は1回だけ。その間に全部届いた・管理本部が確認済みにした・LINE で送れない人（ログに社員番号だけ）は送らない。record は「交通費の送る予定」へ。待っている申請はユーザープロパティ ta-pages-wait（申請ID と最後の写真の時刻だけ）。待つ申請が無ければシートも開かない |
| 枚数が空欄（19g） | 枚目も全枚数も書いていなければ1枚目（全1枚）として扱う。ただし差し替えはしない（別の用紙を消さないため。2枚とも空欄なら両方を足し、同じ日・同じ区間は重複として要確認） |
| 枚数が読めない（19g） | 読めない・枚目だけ書いていない（全1枚のときは1枚目）・枚目が全枚数より大きい → 申請書全体を要確認（枚数）。差し替えはしない |
| 日付 | 読めない・対象月の外 |
| 重複 | 同じ申請に同じ日・同じ出発・到着・手段がもう1行ある |
| TOT（毎朝） | tot-latest.json の日別勤怠（前月1日〜昨日）で、その日に出勤の記録（総労働が0より多い・エラー勤務・出勤の打刻）がない／記録の期間より前で確認できない／TOT の従業員コードがない |

## 5. 確認事項 → 毎朝の業務一覧
- 毎朝7時台（travelApplyDaily）：手で足した明細の照合 → TOT の照合 → 回答の確認 → 要確認の行を業務一覧ファイル（OFFICE_TASK_BOOK_ID）の「臨時の依頼」に**1件1行**で追加（8時の「今日の業務」に出る。土日祝は出ない）。
  - 業務名「交通費の確認：試験さん（11/5 赤井→自宅）」。住所らしい場所の名前は「（場所）」に伏せる。
  - メモ「何が・なぜ・どう直すか」。金額・km・住所は書かず、「交通費明細」の何行目かと申請ID を案内する。期限は回答の日（翌月5日。過ぎていれば今日）。
- スタッフは「交通費明細」の「回答」（必要なら「確認後の値」：車・バイクは合計の km、電車・バスは円）を入れてから［完了］。日付・手段・往復・片道・片道（km）・合計（km）・出発・到着は、その欄を直接直してよい。
- 翌朝：回答か確認後の値が入った行を照合し直す（日付・手段・数字が読めるか。車・バイクは確認後の値が無ければ、往復・片道と片道・合計の km が合うか。電車・バスは確認後の値が無ければ往復・片道が入っているか）。読めれば「確認済み（12/4）」にして確定、臨時の依頼も「完了」にする（確認後の値で金額を計算し直す）。読めなければ、［完了］のあとに出し直す。
- 回答が空のまま［完了］になっていたら、確認事項を出し直す（新しい行。「回答が空のまま［完了］になっていました」を足す）。

## 6-2. 固定店舗（日額×出勤日数）（版 2026-11-20a）
通勤区分が「固定店舗（日額×出勤日数）」の人は申請書なし。6日の締めで「通勤距離」の**日額 × 前月の出勤日数**を「通勤手当」に書く（PAY_writeColumn_。書き込みの決まりは下の7と同じ）。

調査の結果（11/20）：tot-latest.json の日別勤怠（workings）は「前月1日〜昨日」なので、6日の朝（7:05 の中継の前に動いても、5日の夜のデータで）前月1か月分がそろう。打刻（timerecord）は直近7日、シフトは今日から先だけ。**VPS の中継（src/tot-relay.js）は変えない**（安藤さんの決定。打刻漏れは勤怠管理AIで毎日確認している）。

| 項目 | 決まり |
|---|---|
| 出勤日 | 日別勤怠で総労働時間（totalWork）が0より多い日。半日の有給＋残りの半日の出勤は1日。休日出勤も1日 |
| 数えない日 | 全日の休暇（有給・欠勤など）の日 |

| 4日の催促・未提出 | 対象外 |

## 7. 給与反映シート（社労士共有用【リバースHD】）— gas/PayrollSheet.gs（版 2026-11-19c：本番で確かめた形に合わせた）
本番で確かめた形（2026-11-19。見出しと形だけで、金額・氏名は見ていない）。新しい「雛形」や新しい列は作らない。
- 月のタブ：「R{令和}.{M}月分{M+1}月支給」（例 R8.10月分11月支給）。今月分は先頭に★が付く（★・☆・空白は無視して同じ月として扱う）。「テンプレ」タブがある。
- ほかのタブ（隠しタブ・「固定精算の開始・内容について」「固定立替詳細」「交通費計算シート」「従業員コード」など）は触らない。
- 1行目：B列「2026年」・C列「11月支給」（2つのセル）。
- 2行目の見出し：B 従業員番号／C 氏名／D 立替経費／E 通勤手当／F 固定立て替え／G **家賃補助**／H インセンティブ／I 合計（各行 =SUM(D:H)。小文字の =sum の行もある）。**列は見出しの名前で探す**（位置は決め打ちしない）。
- 3行目から1人1行（今は金額がある人だけ）。人の並びのすぐ下に**合計の行**（D〜I が =SUM(D3:D25) の形。テンプレは26行目、10月分は37行目で、月によって位置が変わる）。人の並びの終わりは「従業員番号・氏名が空で、最初の金額の列（立替経費）が =SUM の行」で見つける。
- 合計の行の3行ほど下に固定立て替えの表（D 内容／F 合計金額／G 支払い回数／H・I 期間／J 当月徴収金額）。L列にチェックボックス、M列に「修正箇所」などのメモ。**合計の行より下と、合計の列より右（L・M）には書かない。**

版 2026-11-19d（本番で travelApplyInspectSharoushi を実行したら「合計の行が見つかりません」で止まったため）：
- 合計の行は B〜C 列が結合で B に「合計」。**従業員番号か氏名の欄が「合計」（または両方が空）で、最初の金額の列が =SUM の行**を合計の行とする。
- 人の行は従業員番号が空で氏名だけの行が多く、氏名の空白の有無がばらばら。#N/A の行や、同じ氏名が2行ある月もある。
- 人の照合：まず従業員番号。その番号の行が無ければ、番号が空の行を氏名で照合する（全角半角をそろえ、空白を除いて比べる。氏名は従業員マスタ）。
- 同じ人に当たる行が2行以上：書かずに要確認（管理者への一覧に「同じ人の行が2行以上あるため書かなかった」。ログには人数だけ）。
- #N/A の行・氏名が空の行は対象外（空いている行としても使わない）。
- 既存の行の従業員番号が空でも、番号を書き足さない。人を足すのは番号でも氏名でも見つからない人だけ（二重の行を作らない）。

版 2026-11-19e：本番の「テンプレ」「R8.11月分12月支給」は3行目の合計（I列）が空。足した行の合計の列には、人の行のうち同じ行の =SUM(D?:H?) の形の式がある行を探して同じ形で写す。どの行にも無ければ =SUM(D{行}:H{行}) を入れる。既存の行（空いていた行を使うときも）の空いた合計の欄には書かない。

書き込みの決まり：
- 締めの月のタブが**無ければ**「テンプレ」をコピーして作り、1行目 B・C に支給の年と月を入れる。テンプレに入っている人の行（3〜25行目）は**消さずに使い**、いない在籍者だけを足す。作ったタブだけ、人の行に「金額の列の合計が0なら灰色 #efefef・0でなければ白」の条件付き書式を足す。テンプレそのものは変えない。
- **人を足すとき**：人の並びの中の空いている行（従業員番号・氏名とも空）を先に使い、足りなければ**合計の行の上に行を挿入**する。挿入した行の合計の列には上の説明（19e）の式を入れ、合計の行の =SUM の範囲を広げる（=SUM(D3:D25) → =SUM(D3:D28)。シートが自動で広げていればそのまま）。行ごと挿入するので、下の固定立て替えの表と L・M 列は中身を変えずにそのまま下へずれる。
- タブが**あれば**そのタブに書く。書く金額がある人が並んでいなければ、同じやり方で足して管理者への一覧に「行を足した」と出す。そのほかの行・列・数式・書式は変えず、条件付き書式も足さない。
- 書く列：**「通勤手当」**（交通費の確定額。定期（固定額）の人は「通勤距離」タブの固定額）。従業員番号が一致する行の、空いている欄だけ。
  - 値か式がある欄：上書きしない（同じ値なら何もしない）。違う値は管理者への一覧に「すでに値があるため書かなかった」として出す。
  - 在籍者に見つからない従業員番号：書かずに一覧に出す。
  - 見出しに「従業員番号」「氏名」「合計」や書く列が無い、または合計の行が見つからないタブ：何も書かずに止めて知らせる（直したあと travelApplyCloseAgain でやり直す）。
- 共通の関数 **PAY_writeColumn_(月, 列の名前, [{ code, value }], { people, mode })**：今後の AI の経費申請（立替経費）も、列の名前「立替経費」を渡せば同じ決まりで書ける。通勤手当・立替経費・合計（シートの式）がそれぞれわかる形を保つ。
- 区間ごとの明細は、従業員マスタのファイルの「交通費申請」「交通費明細」に残す（給与反映シートには金額だけ）。
- **構成の確認**：travelApplyInspectSharoushi（＝PAY_inspect。読むだけ）が、タブごとに次をログに出す。氏名・金額は出さない。**本番で一度実行して、結果を見てから on にする**（下の手順4）。
  - 名前・行数・列数・1行目・2行目（見出し）・固定した行・条件付き書式の数
  - 合計の行の位置と式・人の行の数と空いている行の数・人の行の合計の式・見出しに無い金額の列
  - 今月・前月のタブがどれに当たるか
