# 社員管理AI（第1段階：入社・退社・取消）

状態：開発ブランチ `feature/employee-admin` で完成・テスト済み。社員管理AI専用の Apps Script「社員管理AI（本番）」は作成済み（記録のみモード・まだ何も届かない）。
**既存の「勤怠管理」グループLINEで「入社」「退社」と送るだけで登録できる**構成。新しい公式アカウント・グループは作らない。

## 構成（2026-10-27 決定）
```
既存の公式アカウント「REBIRTH 管理本部」
  → Webhook：Cloudflare Workers「rebirth-line-webhook」（LINE署名を確認。違えば401で捨てる）
       ├─ ① 既存の Apps Script「勤怠・アルコールチェック管理」へ、本文をそのまま転送（コード変更なし。社員番号登録・部門登録などは今までどおり）
       └─ ② 勤怠管理グループのイベントだけ、社員管理AIの Apps Script へ転送（合言葉の署名・5分・nonce）
                → 申請・承認・取消 → 従業員マスタ／お知らせ停止
```
- 変更するのは「既存の公式アカウントの Webhook URL」1か所だけ。既存の Apps Script・VPS・DNS・打刻記録は変更しない
- 既存の Apps Script は、【入社】等のグループ発言に反応しない作り（部門登録以外は無視）なので、二重の返信は起きない
- 戻し方：Webhook URL を元の Apps Script の URL に戻すだけ（即時）

## 方式の比較
| | ①Workersで既存Webhookを受ける（採用） | ②既存Apps Scriptに社員管理を組み込み＋Workers | ③VPS中継 |
|---|---|---|---|
| 既存Apps Scriptの変更 | なし | あり | ①②どちらか |
| 署名検証 | Workersで全イベント | 同左 | VPSで全イベント |
| 準備 | Cloudflare無料アカウント | 同左 | DNS・証明書・VPS変更 |
| 戻し方 | Webhook URLを戻す | ＋コードを戻す | Webhook URLを戻す |

## できること
| 操作（勤怠管理グループで送る） | 動き |
|---|---|
| `入社` / `退社` / `取消` の一言 | 入力の雛形を返信（`取消` は取消できる申請の一覧つき） |
| `【入社】…` / `【退社】…` | 形式チェック・従業員マスタと照合 → 申請番号と「承認」「却下」ボタンを返信 |
| 「承認」ボタン | グループの誰でも承認可（本人も可）。72時間以内・1回限り → 予約。反映日が今日以前で自動反映が有効なら、その場で反映 |
| `【取消】申請番号：…` | 反映前なら取消。AIが作ったお知らせ停止の行も消す |
| 毎朝5時台（`employeeAdminDaily`） | 期限切れの処理、反映日が来た予約を従業員マスタへ反映（`EA_AUTO_APPLY=true` のときだけ）、グループへ結果報告 |

- 反映日：入社＝入社日、退社＝退職日の翌日（D列＝退職、N列＝退職日を文字で）。入社前にLINE登録済みならその行に書き込む
- 最終出社日の翌日〜退職日はお知らせ停止（G列＝社員管理AI、H列＝申請番号）。既存の停止判定がそのまま読む
- 記録：`社員管理_申請`・`社員管理_変更履歴`・`社員管理_操作ログ`・`別表記`
- パソコン版LINE：送信者IDは「プロフィール利用に同意した利用者」だけに付く（同意はスマートフォン版で行う）。スマートフォンでもLINEを使う人はパソコンからでも可の見込み。実機で確認する

## 安全対策
- LINE署名（X-Line-Signature）を Workers で確認。署名なし・不一致・改ざんは401で、どちらの Apps Script にも届かない
- 社員管理への転送は合言葉のHMAC＋5分＋nonce。合わない・古い・使い回し・署名の無い直接送信は `NG`
- 申請・承認・取消は勤怠管理グループのメッセージで、送信者が今もメンバーかを毎回LINEに問い合わせる
- webhookEventId で一度だけ処理。承認コードは1回限り
- `EA_MODE`（未設定／record／on）、`EA_AUTO_APPLY` で段階的に有効化。`employeeAdminStop` で即時停止
- 秘密の値は Cloudflare のシークレットと Apps Script のスクリプトプロパティだけに置く（コード・ログ・チャットに出さない）
