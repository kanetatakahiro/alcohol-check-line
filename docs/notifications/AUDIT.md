分類：**本人**／**管理本部**／**上長**（責任者）／**緊急**。優先度：**必須**（法令や事故防止のため欠かせない）・**推奨**・**将来**。

## 8. 設定の統合案（管理本部がチェックを付けるだけで管理する）

前提：**従業員マスタの A〜N 列と、予定の O 列（入社日）は動かしません。** 新しいシートを足し、社員番号でつなぎます。

### 8-1. 新しいシート（従業員マスタのファイル）

| シート | 行 | 列 | 使い方 |
|---|---|---|---|
| **通知の一覧** | 通知の種類（1章の No ごと） | 名前・送信先・タイミング・**状態（止める／記録だけ／送る）**・法令の根拠・担当 | 全社のスイッチ。管理本部が「状態」を選ぶだけ |
| **通知設定（所属）** | 所属（「LINEグループ」シートと同じ名前） | 通知の種類ごとのチェック（例：アルコールチェック・勤怠・希望休・承認待ち・新人案内） | 所属ごとの初期値。リスタイルは希望休のチェックを外す |
| **通知設定（個人）** | 社員番号（従業員マスタから自動で行を作る） | 通知の種類ごとに「空欄＝所属のまま／✓＝送る／✗＝送らない」。**通知上の区分**（管理監督者・役員・出勤予定なし）。上長の社員番号 | 例外だけを書く。今の `LEAVE_REQUEST_EXCLUDE_CODES` はここへ |
| **お知らせ停止**（今のまま） | 期間 | 今のまま。「止めるお知らせ」の選択肢に通知の種類を足す | 休み・休職のときの一時停止 |
| **通知の記録**（新規） | 送った通知1件ごと | 日時・通知の種類・社員番号・結果（送信／記録だけ／送らない：理由） | 「何が誰に届いたか」を1つのシートで |

### 8-2. 判定の順番

1. 全社のスイッチ（「通知の一覧」の状態）が「止める」なら送らない。`DRY_RUN` は非常用の全停止として残す。
2. 「お知らせ停止」の期間中なら送らない（今の範囲の考え方を引き継ぐ）。
3. 「通知設定（個人）」に ✓／✗ があればそれに従う。
4. なければ「通知設定（所属）」のチェックに従う。
5. 通知の種類ごとの条件（シフト・ToT・期限など）で最終的に決める。

### 8-3. 今の設定の移し方

| 今の設定 | 移す先 | 備考 |
|---|---|---|
| `NOTIFY_EMPLOYEES`・`NOTIFY_ADMIN`・`ATTENDANCE_NOTIFY`・`ATTENDANCE_TEST`・`REQUEST_SELF_NOTIFY`・`PUNCH_SELF_NOTIFY`・`INQ_MODE`・`LEAVE_REQUEST_NOTIFY` | 「通知の一覧」の状態 | 移した後もしばらくは両方を読み、食い違いを管理者へ知らせる |
| J列「アルコールチェック対象」 | **そのまま使う**（運転者かどうかの記録のため） | 「通知設定」では、アルコールチェックの列が J列を表示するだけにする |
| `REQUIRE_DEVICE`・在庫シートの「機器所持」 | そのまま使う | 検知器の管理（4-3）と一緒に扱う |
| `LEAVE_REQUEST_EXCLUDE_CODES`（11件） | 「通知設定（個人）」の希望休 ✗、またはリスタイルの所属の初期値 | 新しく入った人も所属で自動で除かれる |
| `TEST_CODES`・`TEST_UNTIL` | 「通知設定（個人）」に「テスト宛先」の印 | － |
| `LINE_ADMIN_USER_ID` | 「通知の一覧」の送信先（個別／勤怠G／安全運転管理者） | 緊急は2系統に |

### 8-4. 進め方（案）

1. 「通知の一覧」シートだけを作り、今の設定を**読んで表示するだけ**にする（動きは変えない）。
2. 「通知設定（所属・個人）」を作り、希望休の案内から使い始める（`LEAVE_REQUEST_EXCLUDE_CODES` を置き換える）。
3. ほかの通知を1つずつ移す。新しく作る通知（4章）は最初からこの仕組みで作る。
