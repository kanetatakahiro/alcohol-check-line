# 交通費（車・バイク）の通勤距離の自動計算と照合（gas/Travel.gs・版 2026-11-18b・**本番未導入**）

申請の受付（申請書の読み取り・確認カード）は別の作業です。このファイルは「距離の表」と「1区間の照合」だけを持ち、申請の処理から `travelCheckSegments` を呼んで使います。
（版 2026-11-18a は別ファイル「従業員店舗間距離計算」を使う作りでしたが、本番に入れず、この版で置き換えました。別ファイルはもう使いません。）

## 1. 使うタブ（すべて従業員マスタのファイルの中。スクリプトプロパティ EMPLOYEE_MASTER_ID のファイル）

| タブ | 扱い | 中身 |
|---|---|---|
| 従業員マスタ | **読むだけ**（列 A〜N・行は変えない。O 列は使わない） | 在籍者＝在籍状況が「退職」でなく、退職日を過ぎていない人（免許証の管理と同じ判定）。社員番号・氏名・所属・拠点を使う |
| 店舗一覧 | **読むだけ**（管理本部が貼る） | A 企業・店舗名／B 住所（郵便番号と住所。改行を含んでよい）／C 電話番号／D 備考（「株式会社リ・バースホールディングス」なら自社の事務所）／E 略語（読点区切り） |
| 住所取り込み | **読むだけ**（管理本部が貼り、取り込みのあと管理本部が消す） | A 社員番号／B 自宅住所。`travelImportAddresses` だけが読む |
| 通勤距離 | このファイルが作り、毎朝そろえる | 社員番号／氏名／所属／自宅住所／住所の更新日／通勤区分／固定額／店舗一覧の各店舗までの距離（車・片道・km・**高速を使わない道**）／計算日 |
| 店舗間距離 | このファイルが作り、毎朝そろえる | 店舗 × 店舗の距離（車・片道・km・高速を使わない道。同じ店舗は 0） |
| 通勤区分の選択肢 | 最初の1回だけ作る（そのあとは変えない） | 通勤区分のプルダウンの選択肢。**ここを直せばプルダウンが変わる** |
| 距離（内部） | このファイルが作る（隠す） | 計算の結果（高速あり・なし・状態・計算日・住所の指紋）。住所・氏名は書かない |

### 「通勤距離」の決まり
- 毎朝、在籍者と同期：新しい在籍者は行を足す（住所は空欄）。退職者・在籍でなくなった人は行を消す。社員番号の順。
- 氏名・所属は従業員マスタから毎朝入れ直す。
- 管理本部が入力するのは「自宅住所」「通勤区分」「固定額」だけ（その3列に薄い黄色）。入力は毎朝の同期でも残る。
- 通勤区分はプルダウン：ガソリンカード／交通費申請（車・バイク）／公共交通機関／定期（固定額）／会社バイク（立替経費）。固定額は「定期（固定額）」の人だけ使う。
- 自宅住所は番地なし（町名まで）でよい。距離は「おおよそ」。通勤区分にかかわらず、住所のある全員を計算する。
- 住所の更新日：住所が入った・変わった日（毎朝の処理か取り込みで、住所の指紋が前回と違えば今日）。
- 計算日：その人の全店舗の距離がそろったときの、いちばん新しい計算日。住所を変えたあと計算し直すまでは、距離の欄は空。
- 「計算できない」：Maps で住所・道が見つからなかった（住所が変わるまで計算し直さない）。

## 2. 距離の計算（travelDistanceDaily・毎朝3時台）
- Apps Script の Maps（DirectionFinder・車＝DRIVING・日本語・地域 jp）。高速を使う道と使わない道（avoid HIGHWAYS）の2回。表には使わない道を出し、使う道は「距離（内部）」に持つ。
- 組：住所のある在籍者 × 店舗一覧のすべて（取引先・自社の事務所も）＋ 店舗どうし（1組1回。逆向きも同じ距離）。
- 計算するのは、まだ無い組・住所（人か店舗）の指紋が変わった組・前回のエラーのやり直しだけ。店舗一覧の行が増えれば、その店舗の組だけ。減れば列と行を消す。
- **TRAVEL_DISTANCE_MODE=on のときだけ計算する**（on でなくても、表の同期は毎朝する）。
- 1日に Maps を呼ぶ回数は **TRAVEL_MAPS_DAILY_MAX（既定 800）** まで。1回の実行は4分半まで。残りは次の日。Maps の無料枠のエラーが出たら、その日は止める。
- ほかの処理と重ならないように：毎日の処理は 8時台〜20時台なので3時台にする。スクリプトのロックは使わない（10分ごと・1時間ごとの処理を待たせない）。同じ処理が重なったときは後のほうが何もしない。
- 安全：従業員マスタの在籍者が0人に見えたら、表を消さずにエラーで止める。

### 件数の見込み（住所取り込み.xlsx は在籍者 50人ぶん・店舗 25件）
- 50人 × 25 ＋ 店舗どうし 300 ＝ 1,550組 → Maps 3,100回 → 1日 800回で **約4日**。そのあとは住所の変更・店舗の追加のぶんだけ。

### Maps の無料枠（2026-11-18 に調べた結果）
- Apps Script の Maps の経路の問い合わせは、1日 **1,000回（個人の Google アカウント）／10,000回（Google Workspace）**（公式「Quotas for Google Services」）。超えると課金ではなく、その日は使えなくなる。
- Workspace の上限（10,000回）は、Workspace のアカウントで動かしていれば自動で適用される。申請して上げる仕組みは見つからない。Business Starter など一部のプランでは適用されないという報告もある（未確認）。
- それ以上が要るときは `Maps.setAuthenticationByApiKey` で Google Cloud のプロジェクトの API キーを使う方法があるが、**Google Maps Platform の料金がかかる**ため、今回は入れていない。
- Workspace なら TRAVEL_MAPS_DAILY_MAX を 3,000 程度に上げられる。ただし1回の実行は4分半までなので、1日に計算できる回数はそちらで決まる（Maps 1回が 0.3〜0.5 秒なら 500〜900回ほど）。

## 3. 住所の取り込み（travelImportAddresses・手動で1回）
- 「住所取り込み」タブの A 社員番号／B 自宅住所から、**在籍者の分だけ**を「通勤距離」の自宅住所に写す。Maps は呼ばない（距離は次の朝から計算）。
- 退職者・従業員マスタに無い社員番号は写さず、その件数と社員番号をログに出す。住所が空の行は写さない。
- ログには件数と社員番号だけ（住所・氏名は出さない）。「住所取り込み」タブは消さない。

## 4. 申請の照合（travelCheckSegments・TRV_checkSegment）
- 入力：`[{ code: 社員番号, from: 出発地, to: 到着地, km: 申請の km }]`（申請書の1行＝片道1区間）。「甲町→自宅」のような1つの文字なら from に入れて to を空に。
- 行き先の判定：「自宅」・店舗一覧の正式名・略語。全角／半角・空白・末尾の「店」・「株式会社」などの揺れはそろえる。読み（かな）や部分一致では当てない。当たらない・2つの店舗に当たる名前は「要確認（行き先がわからない：名前）」で、名前を candidates（略語として追加する候補）で返す。
- 基準は**高速を使わない道**の距離。申請の km が基準より **TRAVEL_TOLERANCE_KM（既定 5）** を超えて多ければ「要確認（申請 X km・自動計算 Y km（…））」。少ないのは問題なし。ETC（高速）の判定は入れていない（別途決める）。
- 「要確認（距離を計算できない）」：自宅住所が無い・表にいない・まだ計算していない・住所を変えて計算し直す前（前の距離で推測しない）・自宅→自宅。
- 「要確認（申請の km が読めない）」：km が数でない。

## 5. 設定（スクリプトプロパティ。どれも安藤さんが設定する）
| 名前 | 中身 | 既定 |
|---|---|---|
| EMPLOYEE_MASTER_ID | 従業員マスタのファイル（**今あるものを使う**） | — |
| TRAVEL_DISTANCE_MODE | on のときだけ Maps で計算する | 未設定＝計算しない（表の同期だけ） |
| TRAVEL_MAPS_DAILY_MAX | 1日に Maps を呼ぶ回数の上限 | 800 |
| TRAVEL_TOLERANCE_KM | 照合で許す差（片道 km） | 5 |

TRAVEL_DISTANCE_SHEET_ID・TRAVEL_MANUAL_DIFF_KM（版 18a）は使いません。

## 6. 本番に入れる手順（承認のあとで安藤さんが行う）
1. Apps Script に Travel.gs（指紋 `8aed84d5b61a189c`）を足す。ほかの .gs は変えない。**Webアプリの再公開は要らない**（受け口を変えていない）。初めて Maps を使うので、実行したときに承認の画面が出たら所有者で承認する。
2. 管理本部が「店舗一覧」タブを貼る。
3. `travelDistancePreview` を実行（Maps を呼ばない・タブを変えない）。在籍者の数・組の数・Maps の回数・日数がログに出る。
4. `travelDistanceDaily` を手で1回実行（TRAVEL_DISTANCE_MODE が無いので計算はしない）。「通勤距離」「店舗間距離」「通勤区分の選択肢」「距離（内部）」ができ、在籍者が並ぶ。
5. 管理本部が「住所取り込み」タブを貼り、`travelImportAddresses` を実行。ログの件数を確かめ、管理本部が「住所取り込み」タブを消す。
6. **Maps を本番で使うのは、ここで承認を得てから**。TRAVEL_MAPS_DAILY_MAX=20・TRAVEL_DISTANCE_MODE=on にして `travelDistanceDaily` を手で1回。数件の距離を地図で確かめる。
7. 問題なければ TRAVEL_MAPS_DAILY_MAX を消す（既定 800）か、Workspace なら上げる。`travelDistanceSetupTrigger` を実行（**トリガーの追加：毎日3時台の travelDistanceDaily**）。

## 7. 戻し方
- 計算だけ止める：TRAVEL_DISTANCE_MODE を消す（表の同期は続く）。
- 全部止める：`travelDistanceRemoveTrigger` を実行してトリガーを消す。必要なら Travel.gs を消す（ほかの .gs は Travel.gs を使っていないので、影響しない）。
- 作ったタブ（通勤距離・店舗間距離・通勤区分の選択肢・距離（内部））は消してよい。従業員マスタ本体・店舗一覧・住所取り込みは変えていないので、戻すものは無い。
- 注意：「通勤距離」の自宅住所・通勤区分・固定額は、管理本部が入れた値。タブを消す前に、要るなら写しを取る。

## 8. 個人情報
- 住所は Google の Maps にだけ送る（Claude API には送らない）。
- ログには件数と社員番号だけ。「距離（内部）」には住所・氏名を書かない（住所の指紋だけ）。GitHub のテストは架空の住所・氏名・店舗だけ。
